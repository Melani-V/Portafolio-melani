Bienvenida

¿De qué trata este portafolio?

Este portafolio reúne información sobre tres modelos de infraestructura y servicios web: la arquitectura tradicional On-Premise, la Infraestructura como Servicio (IaaS) y la Plataforma como Servicio (PaaS). Su propósito es explicar cómo funciona cada modelo, cuáles son sus características y en qué situaciones puede utilizarse.

01 · Local

On-Premise

Los equipos y servidores se encuentran en las instalaciones de la organización.

02 · Infraestructura

IaaS

Se alquilan recursos informáticos virtuales a través de Internet.

03 · Plataforma

PaaS

Se utiliza un entorno administrado para desarrollar y desplegar aplicaciones.

Arquitectura tradicional

1. On-Premise

On-Premise es un modelo en el que una empresa, escuela u organización instala y administra sus propios servidores y equipos dentro de sus instalaciones. La infraestructura física puede incluir computadoras servidoras, almacenamiento, cableado de red, routers, switches, sistemas de respaldo eléctrico y mecanismos de enfriamiento.

¿Cómo funciona?

La organización compra o dispone del hardware, instala el sistema operativo y los programas necesarios, configura la red y mantiene los servidores funcionando. El personal técnico se encarga de las actualizaciones, la seguridad, las copias de respaldo y la solución de fallas.

Características principales

  • Los servidores están físicamente bajo control de la organización.
  • Se necesita espacio, electricidad, conectividad y ventilación adecuados.
  • La organización administra el hardware, el software y la seguridad.
  • La capacidad depende de los equipos disponibles y de la inversión realizada.

Ventajas

  • Mayor control directo sobre los equipos.
  • Posibilidad de adaptar la infraestructura a necesidades específicas.
  • Puede funcionar dentro de una red local sin depender siempre de Internet.

Desventajas

  • Inversión inicial elevada.
  • Mantenimiento y actualizaciones a cargo de la organización.
  • Ampliar la capacidad puede requerir comprar más hardware.
Ejemplo: una escuela que tiene un servidor propio para almacenar archivos, administrar usuarios o alojar un sistema interno.
Infraestructura como Servicio

2. IaaS

IaaS (Infrastructure as a Service) es un modelo de computación en la nube que ofrece recursos informáticos virtualizados, como máquinas virtuales, almacenamiento y redes. El proveedor mantiene los centros de datos y el hardware físico; el usuario configura y administra el sistema operativo, las aplicaciones y los datos que utiliza.

¿Cómo funciona?

El usuario contrata recursos por medio de una plataforma web o una interfaz de programación. Puede crear máquinas virtuales, elegir capacidad de procesamiento, configurar redes y ampliar o reducir recursos según sus necesidades. El proveedor se ocupa del centro de datos y de los servidores físicos.

Características principales

  • Los recursos se entregan mediante Internet.
  • Permite crear y eliminar máquinas virtuales según la demanda.
  • Se puede ajustar la capacidad sin comprar servidores físicos.
  • El cliente sigue siendo responsable de configurar y proteger sus sistemas y datos.

Ventajas

  • Menor inversión inicial en hardware.
  • Escalabilidad y flexibilidad.
  • Acceso a recursos desde distintos lugares con conexión.

Desventajas

  • Depende de una conexión a Internet confiable.
  • Los costos pueden aumentar si no se controlan los recursos.
  • Se requieren conocimientos para administrar sistemas y seguridad.
Ejemplo de clase: KillerCoda. KillerCoda permite practicar en laboratorios interactivos desde el navegador, utilizando entornos temporales y una terminal. Es útil para aprender comandos y trabajar con herramientas sin instalar todo en el equipo personal. Se utiliza aquí como recurso de práctica; no debe confundirse con un proveedor general de IaaS.

Plataforma como Servicio

3. PaaS

PaaS (Platform as a Service) ofrece un entorno listo para desarrollar, probar y desplegar aplicaciones. El proveedor administra la infraestructura y buena parte de la plataforma —como el sistema operativo, el entorno de ejecución y herramientas de desarrollo— para que el usuario se concentre principalmente en el código y los datos de su aplicación.

¿Cómo funciona?

El desarrollador prepara el código de su aplicación y lo sube a la plataforma mediante un panel, repositorio o herramienta de despliegue. El proveedor se encarga de ejecutar la aplicación y mantener los componentes de la plataforma. Las opciones disponibles dependen del servicio contratado.

Características principales

  • Proporciona herramientas y entornos para desarrollar aplicaciones.
  • Reduce la necesidad de administrar servidores y sistemas operativos.
  • Facilita publicar cambios y mantener aplicaciones.
  • El proveedor administra la plataforma; el usuario administra su aplicación y sus datos.

Ventajas

  • Permite concentrarse en programar.
  • Menos tareas de mantenimiento de infraestructura.
  • Herramientas integradas para desarrollar y desplegar.

Desventajas

  • Puede limitar las configuraciones disponibles.
  • Existe dependencia de las características del proveedor.
  • La migración a otra plataforma puede requerir ajustes.
Ejemplo de clase: InfinityFree. InfinityFree es un servicio de alojamiento web gratuito que permite publicar sitios web. En una práctica de despliegue, se cargan los archivos del sitio en el espacio asignado y se configura el dominio o subdominio. Es un ejemplo de hosting web; sus funciones no representan todas las capacidades de una plataforma PaaS completa.

Análisis

4. Comparación de los modelos

Los tres modelos se diferencian principalmente por quién administra los equipos, la infraestructura y las herramientas necesarias para ejecutar aplicaciones.

AspectoOn-PremiseIaaSPaaS
UbicaciónEn las instalaciones propias.Infraestructura del proveedor en la nube.Plataforma del proveedor en la nube.
Hardware físicoLo administra la organización.Lo administra el proveedor.Lo administra el proveedor.
Sistema operativoLo administra la organización.Generalmente lo administra el cliente.Lo administra el proveedor.
Enfoque del usuarioAdministrar toda la infraestructura.Configurar máquinas virtuales y recursos.Desarrollar y desplegar aplicaciones.

Conclusión

On-Premise ofrece control directo sobre la infraestructura, pero requiere inversión y mantenimiento propios. IaaS permite utilizar recursos virtuales sin comprar servidores físicos, aunque el usuario todavía administra sus sistemas. PaaS facilita el desarrollo y despliegue de aplicaciones porque el proveedor mantiene gran parte de la plataforma. La elección depende del presupuesto, los conocimientos técnicos y las necesidades de cada proyecto.

Preguntas frecuentes

6. FAQ

1. ¿Qué significa On-Premise?

Significa que la organización utiliza y administra servidores y equipos ubicados en sus propias instalaciones.

2. ¿Qué es la computación en la nube?

Es un modelo que permite utilizar recursos informáticos —como almacenamiento, servidores y aplicaciones— a través de una red, normalmente Internet.

3. ¿Qué significa IaaS?

Infraestructura como Servicio. Proporciona recursos virtuales como máquinas, redes y almacenamiento.

4. ¿Qué significa PaaS?

Plataforma como Servicio. Proporciona un entorno administrado para desarrollar, probar y desplegar aplicaciones.

5. ¿Cuál es la diferencia principal entre IaaS y PaaS?

En IaaS el usuario administra más componentes, como el sistema operativo; en PaaS el proveedor también administra la plataforma para que el usuario se concentre en su aplicación.

6. ¿Qué es una máquina virtual?

Es un entorno de software que simula una computadora y puede ejecutar su propio sistema operativo y programas.

7. ¿Para qué sirve KillerCoda?

Permite practicar tecnologías y comandos en laboratorios interactivos desde el navegador.

8. ¿Para qué sirve InfinityFree?

Permite alojar y publicar sitios web mediante un servicio de hosting.
